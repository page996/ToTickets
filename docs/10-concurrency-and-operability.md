# 第二阶段：并发与可运维性工程说明

## 1. 适用范围

本阶段只增强本地 mock-first 控制平面的可靠性。它不增加真实平台登录、验证码、设备输入、跨设备广播、账号同步、选票、下单、支付、私有接口或风控规避能力。设备适配器仍只能执行生命周期和只读预览操作，所有自动化测试只针对仓库内合成 fixture。

运行时地址、端口、路径和工具位置继续由版本化配置或环境变量提供；本文件中的 `/api/v1` 和示例指标名是协议/文档常量，不是部署默认值。

## 2. 并发模型

控制平面采用三层互斥边界：

1. **资源键串行化**：同一设备的生命周期、预览和焦点相关写操作按设备键顺序执行；每次写入在同一个临界区内完成适配器调用、状态更新、序列递增、审计和事件发布。
2. **全局协调键**：只读预览的全局单流约束、焦点切换和急停使用明确的全局协调键，避免 check-then-act 竞态。
3. **跨资源并行**：不同设备的独立只读生命周期操作可以并行；共享事件总线、审计和缓存均有显式容量上限，达到上限时返回稳定的可重试错误或淘汰慢连接。

串行化器不执行任何用户输入，也不隐式重放命令。队列只保存已通过 DTO、策略和人工确认校验的安全生命周期/观察操作；操作失败时只释放当前键，不把失败操作重新排入队列。

## 3. 状态原子性

repository 对外只返回不可变快照/深拷贝；生产代码不能持有可变共享对象并在多个异步请求之间直接修改。状态写入通过受控 mutation 完成，并同时更新：

- `state`、`stream`、`focused` 等互斥字段；
- `lastSeenAt`；
- 单调递增的 `sequence`；
- 一条脱敏审计记录；
- 一条带相同序列的 CloudEvent。

事件发布失败不能提交半更新状态；适配器异常也不能产生“已成功”事件。重复的安全命令可以保持幂等，但每次请求的确认票据和幂等语义仍由服务端重新校验。

## 4. 背压与资源上限

以下上限必须来自运行时配置，并在健康端点中以非敏感计数暴露：

| 资源 | 行为 |
| --- | --- |
| 设备登记数 | 达到 `max_devices` 时拒绝新登记，返回 `device.busy` |
| 幂等缓存 | TTL 到期后清理；超过容量按最旧完成项确定性淘汰；正在执行的 promise 不被淘汰 |
| 确认票据 | TTL 到期后清理；超过容量拒绝签发并要求先释放/等待 |
| 事件历史 | 只保留配置窗口；游标无法满足时发送 `reset_required`，客户端重新取快照 |
| WebSocket 连接 | 超过客户端配额拒绝新连接；单连接发送缓冲超过阈值时以 1013 关闭慢客户端 |
| 审计保留 | 按时间和配置上限清理，导出只返回脱敏字段 |
| 日程与定时器 | 达到 `max_schedules` 后拒绝新建；每条日程的提醒数继续由 DTO 上限约束 |
| 入站 WebSocket 帧 | `maxPayload` 由配置注入底层 NestJS `WsAdapter`，超限连接由协议栈关闭 |
| 操作调度队列 | `operation_queue_max_queued` 限制每个键控/全局调度器的等待项；达到上限以可重试 `device.busy` 拒绝，失败项释放后续 FIFO 项 |

任何队列或缓存都必须能回答当前长度、容量、拒绝数和淘汰数。不得用无限数组、无界 EventEmitter 监听器或无限重连定时器作为隐式队列。

## 5. 健康与就绪

控制平面提供只读诊断：

- `GET /api/v1/health/live`：进程事件循环仍能响应时返回成功；不依赖设备或外部工具。
- `GET /api/v1/health/ready`：配置、核心内存存储、事件总线和资源配额可用时返回成功；不把“有设备在线”误判为进程就绪。
- `GET /api/v1/health/diagnostics`：返回 schema 版本、当前设备数、事件序列、历史占用、缓存占用、WebSocket 连接数、拒绝/淘汰计数和启动以来 uptime；禁止返回地址、凭据、令牌、屏幕帧或环境变量原文。

健康检查必须是无副作用的，不触发设备启动、预览、重连、提醒或任何用户动作。响应字段采用 `snake_case`，并通过现有响应拦截器附加 `request_id`。

## 6. WebSocket 恢复协议

连接先接收同步帧，再接收 replay 事件。replay 采用有界批次，并在批次间让出事件循环；实时事件进入发送队列时遵循同一上限。慢客户端只影响自身：服务端记录原因、关闭 1013，并保留其他客户端的事件流。

客户端在同一时刻最多一个活动快照请求；事件突发只设置 dirty 标记，活动请求完成后最多再执行一次 trailing refresh。重连使用指数退避和抖动，并在页面不可见时暂停高频轮询；重新可见后立即做一次快照同步。

`stream_id` 或 `sequence` 不匹配时，客户端只请求 REST 快照，不依据过期事件执行写命令。

## 7. 验收指标

指标为本地合成负载的实测基线，不代表真实平台购票速度或成功率承诺：

- 32 台 mock 设备，至少 32 个 WebSocket 客户端；
- 500--1000 个受控 REST 操作，包含同设备并发、跨设备并发和重复幂等键；
- 同一设备返回的 `sequence` 严格单调且无重复提交；
- 同一幂等键的安全操作最多执行一次；
- 负载期间健康探针持续可响应，无未处理 rejection；
- 人为制造事件间隙、服务重启、慢客户端和连接恢复，均能得到明确 reset/关闭/重连结果；
- 记录 p50/p95/p99、错误率、拒绝数、淘汰数和恢复耗时，不伪造固定性能承诺。

## 8. 回滚与交付

本阶段不改变外部依赖。新增必填操作队列配额使 API 配置契约升为 `runtime-config.v3`，并同步 schema、示例和测试；旧 v2 配置会明确 fail closed。任何性能优化都可通过调整 v3 配额或恢复前一版代码/配置回退；不删除已有审计、fixture 或构建缓存。交付前必须运行合规扫描、依赖/SBOM 校验、API/控制台测试、类型检查、Rust 检查、负载/故障测试和 Tauri 启动冒烟。
