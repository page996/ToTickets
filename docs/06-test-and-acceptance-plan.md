# 测试与验收计划

## 1. 测试原则

测试围绕“控制台可靠地支持人工操作”展开，不以真实平台订单成功为指标。所有自动化只面对 `local.mock.ticketing`、合成设备或脱机 fixtures。

## 2. 测试层级

### T1：静态与单元测试

- schema 严格校验、时间区间、时区和单调倒计时。
- 状态机合法/非法转移、序列号去重和幂等键。
- 策略拒绝未知能力、批量目标、禁止命令词和敏感字段。
- 日志脱敏、审计哈希链、保留策略。
- 子进程参数数组和 allowlist 构造。

### T2：契约测试

- REST OpenAPI 请求/响应与错误码。
- WebSocket CloudEvents envelope、schema URL、sequence gap resync。
- `DeviceAdapter` 的 Mock、ADB 只读实现使用同一端口测试。
- 适配器崩溃、断连、重连和超时语义。

### T3：集成测试

- 控制平面 + SQLite + MockAdapter 的完整状态流。
- 多设备生命周期并发，但只测试启动/停止/健康，不发送输入。
- 时钟漂移、系统睡眠、重复提醒和急停。
- 预览流启动/停止、内存预算、帧过期和焦点切换。

### T4：UI/E2E 测试

- 设备网格、过滤、焦点选择、确认弹窗、错误恢复和审计查询。
- Playwright 只访问本地控制台和 mock App；CI 断言请求域名不包含 `damai.cn`，包名不包含真实平台包名。
- 视觉回归不保存真实画面；用合成色块和文字。

### T5：人工验收

- 单台实体 Android 设备或官方 AVD：用户自行登录并操作任意非交易测试页面，控制台只显示状态和画面。
- 明确验证验证、实名、订单、支付页面没有任何系统自动动作。
- 断开 USB/网络、关闭模拟器、改变时钟后确认提示和恢复路径。

## 3. 强制负向测试

以下用例必须失败，并产生 `policy.denied` 或对应稳定错误：

1. `POST /devices/{id}/commands/click`。
2. 一个命令包含两个以上设备且声明输入能力。
3. 请求体包含 `password`, `otp`, `id_card`, `payment_token` 等字段。
4. 过期或缺少操作者确认票据。
5. 适配器尝试执行 `adb shell input` 或未登记的可执行文件。
6. WebSocket 客户端使用旧序列直接提交设备命令。
7. CI 测试尝试访问真实大麦域名或安装未知签名的测试 APK。
8. 时钟偏差超阈值时仍试图发送“就绪”提醒以外的动作。

## 4. 性能与可靠性目标（首版建议）

| 指标 | 目标 | 测量方式 |
| --- | --- | --- |
| 设备健康事件延迟 | p95 < 500 ms（8 台设备） | MockAdapter 负载测试 |
| 提醒触发偏差 | p95 < 250 ms；时钟不可信时不触发 | 单调时钟测试 |
| WebSocket 重连恢复 | 5 秒内完成快照同步 | 注入断网/序列缺口 |
| 急停 | 2 秒内停止所有适配器进程 | 进程树集成测试 |
| 敏感数据落盘 | 0 个允许字段 | schema、日志和文件扫描 |
| 事件丢失 | 0 个确认/拒绝事件；断线后可重放 | append-only + sequence 测试 |

这些是工程基线，不代表真实购票速度或成功率承诺。

## 5. 验收门槛

### 第二阶段并发与可运维性门槛

- 32 台 mock 设备和 32 个 WebSocket 客户端下，健康探针持续可响应；
- 同设备并发写入保持严格单调 `sequence`，全局预览约束无 check-then-act 竞态；
- 同一幂等键的并发请求最多执行一次，缓存和确认票据达到上限时确定性拒绝或淘汰；
- replay 间隙、stream 重启和慢客户端均有明确恢复/关闭语义，不能拖垮其他连接；
- 记录实际 p50/p95/p99、错误率、拒绝数、淘汰数和恢复耗时，不用静态承诺替代测量。

### Gate A：文档与策略

- AGENTS、ADR、范围、威胁模型和接口契约通过人工审阅。
- 许可证清单和第三方来源可追溯。

### Gate B：Mock MVP

- T1-T4 全部通过；负向测试覆盖率 100%。
- 可完成一次多设备生命周期演练和提醒演练。

### Gate C：只读设备 PoC

- 单台官方 AVD 或实体设备通过 T5；屏幕流不落盘。
- 任何输入能力默认关闭，审计和急停可用。

### Gate D：扩展评估

- 只有用户再次批准、法律/许可复核和安全评审通过，才可增加新的供应商适配器或人工透传能力。

## 6. 测试数据策略

测试数据由 fixture 工厂随机生成；姓名、手机号、证件号和支付值使用明显的合成标记，且不符合真实格式或使用保留域名。测试日志在 CI 结束时清理，失败 artifact 只保留脱敏摘要。
