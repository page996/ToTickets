# 工程变更审批协议

## 目的

把用户要求的“每一步说明原因、方案和结果”落成可执行流程，并区分只读检查、普通写入和高风险动作。

## 变更等级

| 等级 | 示例 | 最低要求 |
| --- | --- | --- |
| R0 只读 | 列目录、读文档、查询公开来源 | 进度说明；不改状态 |
| R1 本地文档/代码 | 新建或修改仓库文件、运行本地测试 | 说明文件范围、预期、回滚和验证 |
| R2 依赖/进程/设备 | 安装依赖、启动模拟器、访问 ADB、开启端口 | 说明供应商、权限、数据流和停止方式；单独批准 |
| R3 外部账户/交易 | 登录真实账号、真实订单、支付或第三方写入 | 本项目禁止自动执行；只能由用户直接完成并另行人工确认 |

## 记录格式

每次 R1/R2 变更在对话中说明：

- 原因：为何现在需要。
- 方案：将执行什么，哪些替代方案被排除。
- 预期：文件、进程或测试的可观察结果。
- 风险：数据、许可证、设备和可逆性。
- 实际结果：完成、偏差、失败和后续动作。

## system prompt 的边界

Codex 的隐藏 system prompt 由平台管理，项目不能写入或修改。仓库级 `AGENTS.md` 是可被代理读取的项目约束；本协议、ADR 和安全文档是面向人和工具的可审计补充。任何声称已修改隐藏 system prompt 的实现都应视为不可信。

## 环境与依赖审批

新增依赖、工具链、模拟器或打包组件属于 R2 变更，即使安装动作发生在隔离环境中也必须记录：精确版本、来源、许可证、权限、缓存/下载位置、锁文件变化、SBOM 组件 ID、回滚方式和新机器复现步骤。不得以“系统已经安装”为理由跳过记录。
