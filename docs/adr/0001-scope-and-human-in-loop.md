# ADR-0001：范围与人工闭环

- 状态：已采纳
- 日期：2026-08-25
- 决策人：项目发起人和实现代理共同确认的首阶段边界

## 背景

原始设想包含多账号同步、精确点击、验证码之后的批量购票和支付交接。这些行为会直接影响平台反自动化控制、订单公平性和个人敏感信息安全，也无法通过公开稳定接口保证正确性。

## 决策

系统只做人工购票辅助：设备/模拟器生命周期、只读屏幕、健康监控、倒计时提醒、人工确认、审计和 mock 测试。真实大麦页面上的登录、验证码、票档选择、实名确认、下单、锁票和支付全部由操作者完成。

控制平面不提供通用点击/输入 API。若未来需要远程操作，只能是单设备、可见窗口、一次一台、用户直接交互的 UI 透传，并且默认关闭；不得录制、重放、广播或脚本化。

## 后果

- 不能承诺毫秒级自动抢票或提高购票概率。
- 可以可靠地复用设备管理、观察、提醒、审计和故障恢复能力。
- 所有自动化测试可在 mock App 中进行，不会触碰真实账号和真实订单。
- 任何要扩大到真实平台自动化的需求都必须新建 ADR，并通过合规、安全和用户审批门槛。
